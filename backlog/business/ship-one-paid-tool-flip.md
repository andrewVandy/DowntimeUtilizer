## Objective

Build and package one genuinely small, useful, paid developer tool or
script end-to-end in a single sitting — a deliberately low-scope test of
the "vibe coding" thesis (`ai-monetization-overnight-automation` category
#14) using this project's own toolchain, chosen as a fast, cheap
experiment rather than a bet-the-run project.

Definition of done: one small tool (a CLI, a script, a tiny library, a
single-purpose Obsidian/Raycast/VS Code extension — whatever the chosen
idea actually needs) built, tested, documented, and packaged for sale
(Gumroad digital download, or a GitHub repo with a paid Pro tier via
GitHub Sponsors) — publish/account steps are the same manual handoff
pattern as this project's other business items.

## Context

Category #14's own counter-signal is the reason this is scoped small
instead of ambitious: 45% of AI-generated code reportedly contains
vulnerabilities, and there's a well-documented "90% problem" where
AI-built projects stall on the last mile of integration/debugging without
real engineering oversight. Keeping this item's scope small (a tool, not
a product) is a deliberate hedge against that failure mode — something
genuinely finishable in one pass rather than another half-built SaaS.

This is also a direct, cheap test of category #15's central caution
(agents producing output with zero revenue): because the scope is small,
it's a fast way to learn whether "build something small and useful, sell
it for $10-30" actually converts to any real transactions at all, before
this project commits more effort to the larger `chrome-extension-
ai-wrapper` or `smb-ai-agent-template-kit` items above.

**Pick the tool idea from a real, felt gap** — ideally something adjacent
to this project's own domain (Claude Code productivity, per the sibling
`claude-code-productivity-tools` research item) rather than a generic
idea, since that research already mapped what's free/open-source in this
space and what gaps remain unfilled.
