## Objective

Prepare a complete, ready-to-use freelance/consulting portfolio package
that positions the user to sell Claude-Code-driven MVP/automation
development at the real rates documented in research (category #3:
average AI-coding freelancer ~$12,400/month on Upwork, junior $50-100/hr,
solo devs delivering $20-75k-agency-quality MVPs for $5-25k, retainer
model $3,000-8,000/month/client). Definition of done for v1: a written
case-study document, a rate card, 1-2 concrete demo/sample projects (small,
real, working code — not mockups), and draft outreach/profile copy for
Upwork/Contra-style platforms — all checked into this file's directory,
packaged and ready. Actually creating platform accounts, negotiating with
real clients, and signing contracts are manual steps for the user (see
Context), same pattern as the Gumroad-account step in the sibling
`gumroad-venture-factory-template` item.

## Context

Spawned from `backlog/research/ai-monetization-overnight-automation.md`
(category #3, Freelance AI Development). This category has among the
strongest independently-sourced numbers in that research (Upwork platform
data, not just vendor marketing) and directly reuses this project's own
production asset — Claude Code itself, and this repo as a working
demonstration of autonomous-agent-driven delivery.

**Why this needs a portfolio-prep item, not just "go get freelance work"**:
per `POLICY.md`, a routine cannot create real freelance-platform accounts,
negotiate with real clients, or represent the user in business
communications without that being the explicit stated objective and
without exposing the user's real identity to a third party autonomously —
account creation and client interaction stay manual, same reasoning as
Gumroad's payout/identity requirement in the sibling business item. What
*is* safe and valuable for a routine to build unattended: the durable
assets (case study writeup, rate card, demo code, draft copy) that make
the eventual manual step (the user creating a profile and applying) much
faster and higher-quality than starting from a blank profile.

**Distribution plan** (per the monetization research's category #15
lesson — a plan for actually getting clients, not just being available to
hire): the "case study" *is* the distribution mechanism here, not a
separate step — a concrete, verifiable "I used Claude Code to ship X in Y
hours" writeup is what differentiates a $200-600/hr consultant profile
from a commodity $99/mo generalist one (per the research's category #2/#3
notes on what separates the two tiers). This project itself — an
autonomous overnight backlog system — is a legitimate, unusual case study
asset once it has a few finished, shipped items in `done/` to point to.

**Honest confidence note**: scored `confidence: 3`, not higher, because
the actual revenue-generating step (a human client saying yes) is
irreducibly outside what an unattended run can do or verify — this item's
"done" state is "ready for the user to go sell," not "revenue generated."
